# 字幕协校（自托管）

基于 Python 标准库 + SQLite + 浏览器单页应用的字幕协作校对工具，零第三方依赖。

## 功能

- 上传 **UTF-8 编码的 SRT / VTT** 文件，解析为带稳定标识（uid）的字幕条；格式错误的文件直接拒收，**不会创建项目**
- 网页端修改字幕文字与时间、插入或删除字幕条
- 每次保存生成一个新版本，可查看历史版本并**导出任意指定版本**为 SRT 或 VTT
- 提交须携带编辑时的基线版本：
  - 期间他人只改了**其他**字幕条 → 自动三方合并
  - **同一**字幕条被双方修改、或一方修改一方删除 → 返回双方状态（409），由人工逐条选择保留哪一方，**绝不自动覆盖**
- 每次合并后校验整轨：时间非负、起点早于终点、字幕条互不重叠、文本非空；任一不合规则**整批拒绝**并逐条说明原因

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**

数据库文件在首次启动时自动初始化，持久化在名为 `subtitle-data` 的卷中（容器内路径 `/data/app.db`）。

## 本地运行（无需 Docker）

要求 Python 3.8+，无第三方依赖：

```bash
python3 app.py
```

同样访问 http://localhost:8000 ，数据库默认创建于 `./data/app.db`。

## 配置（环境变量）

| 变量      | 默认值                          | 说明           |
| --------- | ------------------------------- | -------------- |
| `PORT`    | `8000`                          | HTTP 监听端口  |
| `DB_PATH` | 容器 `/data/app.db`；本地 `./data/app.db` | SQLite 数据库路径 |

修改端口示例：`PORT=9000 python3 app.py`，或编辑 `docker-compose.yml` 的 `ports` 映射。

## 使用流程

1. 首页上传 `.srt` / `.vtt` 文件创建项目（可自定义项目名）
2. 打开项目进入编辑器：修改时间（`HH:MM:SS,mmm`）与文本、插入/删除字幕条
3. 点击「保存为新版本」；若与他人冲突，页面会列出双方状态供逐条选择后重新提交
4. 「历史版本」中可查看任意版本（只读）并导出 SRT / VTT

## API 一览

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET  | `/api/projects` | 项目列表 |
| POST | `/api/projects?name=&filename=` | 上传文件创建项目（请求体为文件原始字节） |
| GET  | `/api/projects/{id}` | 项目详情 + 最新版本字幕 |
| GET  | `/api/projects/{id}/versions` | 版本列表 |
| GET  | `/api/versions/{id}` | 指定版本字幕 |
| GET  | `/api/versions/{id}/export?fmt=srt\|vtt` | 导出指定版本 |
| POST | `/api/projects/{id}/edits` | 提交编辑：`{base_version, note, cues:[{uid,start_ms,end_ms,text}]}`；冲突返回 409，校验失败返回 400 及原因 |

## 合并与校验规则

- 字幕条的 `uid` 在导入时生成并跨版本保持稳定；新增字幕条在保存时分配新 uid
- 三方合并以提交携带的 `base_version` 为共同祖先：单方改动直接采用；双方改动一致（含都删除）不视为冲突；双方改动不一致或一方改一方删 → 冲突
- 冲突响应包含 `head_version` 与每条冲突的 `base / ours / theirs` 三方状态，人工选择后以头版本为新基线重新提交
- 校验在每次合并（含直接应用）之后执行，失败即整批回滚，不产生新版本
